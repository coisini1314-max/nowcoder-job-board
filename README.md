# 校招雷达

## 使用看板

离线预览打开 `校招雷达.html`，页面内置当时的岗位快照和本机关键词档案。部署后的网页用「导入关键词档案」选择本地 `profile.json`。网页从当前浏览器读取档案和投递状态，匹配在页面内计算。离线预览、不同浏览器和 GitHub Pages 的状态分别保存。

每个版本独立核对。分数由 JD 职责、要求和标题的关键词覆盖率以及标题方向覆盖率构成。同分按岗位方向和基准版本排序。70 分及以上进入待投清单。已投递和跳过自动从待投清单排除，失败可重新处理。已知届别、学历或截止时间冲突、JD 缺失、入口未确定时最高 69 分。关键词同义归类只是初筛，差距表示该版本未检出证据。核对 JD 原文里的专业、经历和工具要求后再申请。

每份 PDF 按文件数字尾号建立独立的版本。文件日期、院校或实习记录出现冲突时，应在招聘页核对。

## 辅助投递

在你平时使用且已登录牛客的 Chrome 打开看板。点「一键投递」打开岗位并在原看板显示推荐 PDF 文件名。打开岗位会复用该浏览器的正常登录状态。能使用牛客网申助手的企业表单可通过其入口填充字段。牛客直投以牛客页面显示的简历选择为准。核对并选定 PDF，在招聘页面手动提交。获得成功提示后，在看板手动选「已投递」。平台投递记录与看板状态分别维护。未找到对应 PDF、ATS 不支持自动填表或遇到验证码时，由你在招聘页处理。

牛客官方 Skill v1.1.6 可提供岗位查询和投递指引。云端定时任务只读取公开校招网页，无需牛客账号、登录会话或授权令牌。定时抓取按电商运营、海外运营、市场营销、销售管培生和广告投放轮取最多 20 条，定向结果不足时用公开校招列表补足。数据源每日可能返回相同职位或与方向无关的职位。列表非直投条目如果没有可靠详情地址，会链接回校招列表。

## 本地更新

```sh
python3 scripts/refresh.py
python3 -m http.server 8765 --bind 127.0.0.1 --directory site
```

打开 http://127.0.0.1:8765 后可导入私有档案。重新扫描简历需安装 `pdfplumber`，再运行 `python3 scripts/scan_resumes.py 简历文件夹 --year 毕业年份 --degree 最高学历`。默认扫描带数字尾号的 PDF，可用 `--pattern` 限定具体文件名，使用 `--focus 1=电商运营` 指定版本方向，使用 `--preferred 1,2` 指定同分顺序。修改简历后需重新生成并导入档案。PDF、关键词档案和离线个人看板均应留在本地。

```sh
python3 scripts/preview.py /路径/校招雷达.html --profile private/profile.json
```

## GitHub Pages

1. 把本项目的公开文件推送到目标仓库的 `main`。只提交 `site/`、`scripts/`、`.github/`、`.gitignore`、`README.md`。确认提交列表里没有 `private/`、私人预览、原始简历或凭据。
2. 在仓库的 **Settings → Pages → Source** 选 **GitHub Actions**。
3. 打开 **Actions → 更新牛客岗位并发布看板 → Run workflow**。成功后从运行结果打开 Pages 链接，并在网页导入本机档案。

每天北京时间 08:23 排程，实际启动受 GitHub 排队影响。任务从牛客公开校招页按方向去重取 20 条，原子更新 `site/jobs.json`，提交该文件并在同一次任务发布。抓取或校验失败时保留上一版网页。仓库需允许 Actions 使用 `GITHUB_TOKEN` 向 `main` 推送更新。公开仓库长时间无活动时，GitHub 可能停用排程，可在 Actions 中重新启用。
